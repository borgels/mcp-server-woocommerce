# Changelog

## 0.1.1

- Gateway results: the data is now in the text block too. A successful
  `callTool` result has one text block with the summary, a blank line and
  then `structuredContent` as compact JSON (`summary\n\n{...}`), as the MCP
  specification recommends for tools that return structured content. Before,
  the text held only the summary, so a client that reads only the text (as
  Claude does) got no data. The JSON is built from the final, redacted copy,
  so it is exactly `structuredContent`, and the sink check covers it. Error
  results and `structuredContent` are unchanged.
- Errors leave in final form: every error a gateway throws is a fresh
  error with no `cause`, a `stack` of just `name: message` (no frames,
  paths or function names), and name, message and stack masked against the
  secret; the sink check runs on the finished object, its non-enumerable
  fields included.
- Every element of a failure list (`failures`, `failure`, `errors`,
  `error`, `warnings`), at any depth and whatever its fields, becomes
  `{ status?, message }` with our own text; a failure context such as
  `metadata` or `amount` holds through wrappers such as `data`.
- Network, timeout and redirect errors name the method only, not the
  configured address.
- The sink check: every output of a gateway (the tool list, results, audit records and stderr lines, construction errors) is checked in its
  final form, and one that holds a piece of 6 characters of the key is
  replaced by a fixed fallback (`src/fallbacks.ts`): a withheld result, a
  fixed audit record or line, or the fixed refusal. A key that shares a
  piece with a fallback or with the tool list is refused at creation.
- Key admission: printable ASCII (0x21-0x7E) of at least 16 characters,
  checked before anything is built from the key; the corpus of our own
  string literals stays as a cheap first filter.
- A text in a failure list of a successful answer (`failures`, `errors`,
  `warnings` and the like) is replaced by our own text, like a failure
  object.
- Key admission: a gateway refuses a key shorter than 16 characters or one
  that shares a 6-character piece with any string literal in `src/`
  (`src/fixed-corpus.generated.ts`, generated by `scripts/fixed-corpus.mjs`
  and checked by a test). The refusal never repeats the key.
- Every string leaving a gateway passes the instance's redactor as the last
  step: results (a second pass after the depth placeholder), construction
  errors, and whole stderr lines with their prefix.
- A nested failure is any object with a status of 400 or more, an `error`,
  or `errors`, `message`, `detail` or `description` in a failure context
  (`failures`, `errors`, `metadata`, ...); it keeps only its status.

- The threat model's guarantees apply to the gateway (`./gateway`); the
  standalone MCP server keeps best-effort redaction. The MCP server now runs
  each call in a scope with its redactor, and every audit record (finish and
  policy refusals included) and every audit failure written to stderr is
  redacted with the same redactor, through the shared `redactDeep`.
- The redaction marker is `‹redacted›` (non-ASCII brackets). A gateway
  refuses a key that contains it or shares a 6-character piece with it.
- `nestedFailuresAsStatus` keeps only the status and our own text in a
  failure object (no message, code or detail); `create_item` uses it too.
- A network error names a system error code only from a fixed list. Errors
  about the base URL or the listen address no longer quote the scheme or the
  address.

- Threat model in the README and NEW-SERVER.md: what is guaranteed about the
  key (never persisted or shared; no vendor text in errors; results only to
  the key's tenant) and the residual risk (a vendor echoing the key back in
  data, transformed).
- `redactDeep` also checks the string form of numbers, booleans and bigints
  and replaces a match with the string `"[REDACTED]"`; it serialises a
  `toJSON` value (a Date) before redacting it. The gateway redacts a result
  first and copies it as JSON afterwards, so a deep result cannot exhaust
  the stack.
- `nestedFailuresAsStatus`: failures reported inside a successful body
  (`metadata.error`, `failures[].error`) become status-only text; used by
  `get_item`.
- An error thrown while reading a successful body becomes a fixed text.
  Errors about options no longer quote the value or the base URL's host.

- `./gateway`: every result is redacted with the instance's key, text and
  structured data, object keys included. `redactDeep` replaces values nested
  deeper than 64 levels instead of passing them on unredacted.
- `nestedFailureText(error)` for failures kept inside an otherwise returned
  result (the HTTP status or a fixed text), used by `get_item` with the new
  `includeHistory`.
- No upstream text in errors: `ExampleHttpError` keeps only the status, our
  hint and a parsed Retry-After (the body is discarded unread; `payload` and
  `errorCode` are gone), a redirect error does not quote the `Location`, a
  network error names only a system error code, and audit records carry no
  vendor code. Breaking for code that read `payload` or `errorCode`.
- The redactor also removes the JSON-escaped form of a key and any piece of
  it of 6 characters or more. Configuration errors no longer quote the
  rejected value.

- `./gateway`: `createExampleGateway` takes `policy` (`enableWrites`,
  `disabledTools`, `audit` sink). An instance with a host policy reads no
  policy or audit variable from the environment (`EXAMPLE_ENABLE_WRITES`,
  `EXAMPLE_DISABLED_TOOLS`, `EXAMPLE_AUDIT_LOG`,
  `EXAMPLE_ALLOW_CUSTOM_BASE_URL`), so tenants in one process can have
  different settings. Without `policy` nothing changes.
- `./gateway`: every gateway call runs in a call scope of its own (policy or
  environment, sink, redactor), so a call made from inside another
  instance's call (from its audit sink or its fetch) never inherits that
  instance's policy, sink or redactor.
- `createExampleGateway` refuses an `apiKey` shorter than 8 characters,
  the shortest secret the redactor protects.
- Audit records are redacted as a whole with the instance's redactor before
  they reach the sink or the log file: tool name, input field names, caller,
  request id and reason, refusals included. Text is redacted before it is
  cut short, so no part of a key survives a cut.
- `exampleToolCatalog` entries carry `broad`, the mark for a tool that can
  read more than its name says. A tool declares it in the tool table
  (`broad: true`); it defaults to false. Hosts that grant tools per role read
  it from the catalog instead of setting it by hand.
- `./gateway`: `createExampleGateway` requires `apiKey` and `baseUrl` and no
  longer falls back to `EXAMPLE_API_KEY` and `EXAMPLE_BASE_URL`; a missing
  value throws when the gateway is created. The stdio and HTTP transports
  still read the environment. Behaviour change for embedders.
- Secret redaction is per client instance (`SecretRedactor`) instead of a
  process-wide registry, so gateways for different tenants in one process
  never share or retain each other's keys.
- `./gateway` exports `exampleToolCatalog`, a frozen, typed catalog of every
  tool with its schema, risk level and the upstream requests it may make,
  generated from the shared tool table, and the `ExampleGateway` type.

## 0.1.0
